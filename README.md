## Secure Authentication System 

## Overview

In this assignment I created a Python command-line authentication system. The point was to make something resembling the way a basic system of logging in works where a user can register, log-in, change password, delete their account. I also included audit log in order to record all the activities in the system with a date which is critical in terms of security.

The entire project is divided into three python files - auth.py which has all the authentication related functions, utils.py which contains helper functions and main.py which is just a run of the menu. The files also include a users.json file which contains the accounts and an audit.log file which tracks the activity.

 ## Project Files

 a. auth.py - contains authentication related functions such as login, registration, logout, password update, log viewing, and account deletion

 b. Utils.py-  Contains helper functions such as password hashing, logging, password strength validation, and file handling

 c. main.py - It shows the menu to the user and calls the right function from auth.py.

 d. users.json - It stores all the registered user accounts

 e. audit.log - it records every action with a timestamp

 f. README.md - contains project documentation 

 ## Modular Structure

The system was later refactored into multiple modules to improve code readability, organization, and maintainability.

- main.py handles the user interface and menu system.
- auth.py contains all authentication and account management functions.
- utils.py contains reusable helper functions such as password hashing, logging, password validation, and file operations.

This modular approach makes the project easier to manage and follows better software development practices.

## Features and how to Use Them

 a. Register - 

This allows the user to make a new account. The user types in a username and a password. The system follows up on the following: The username must contain at least 3 characters and the password must be strong enough, the password must consist of at least 6 characters, one uppercase letter, one number and one special character such as!, us, 5, or 8. When any of these fails, it will inform the user of what is wrong and they may resume trying. 

 b. Login - 

The user gets 3 login attempts. If the wrong password is entered 3 times, the account becomes temporarily locked for 60 seconds. During this time, the user cannot attempt another login. The system also displays the remaining lock time.

 c. Update Password -

This allows them to change your password. The user needs to enter their current password with the aim of establishing that it is them. Then the user types in a new password twice, it is because this way they will not save a typo. The new password also should undergo the same strength check as registration and cannot be identical to the old password.

 d. Logout - 

 This logs the user out, prints logout time and returns to the main menu. The system also checks whether a user is currently logged in or not before allowing the logout. 

 e. View Log -

This will read the audit.log file and print whatever is contained in it. It displays all the action that has taken place registrations, logins, failed attempts, deletions and so on. It also waits after viewing before the user can press Enter and the menu is returned.

 f. Delete Account -

This is used to permanently delete a user account. The user needs to input the correct password and then input yes to confirm. When the user types something other than yes the deletion will be cancelled. The deletion is also displayed in the log file.

 g. Clear log - 

This deletes the audit.log file. It asks the user to confirm first by typing 'yes'. Although it is cleared, it leaves a new entry in the log indicating that the log was cleared and so there is always a record that a clear occurred.

 h. Exit - 
 Closes the program.   

## Security Features 

a. Password Hashing -  

How I implemented it - 
I used to hashlib.sha256 to hash passwords before saving them to users.json. The actual password is never stored.

Why is it important - 
If someone gets access to the JSON file, they cannot read the real passwords, they can only see the hash.

b. Password Strength Validation - 

How I implemented it - 
The strong_password() function checks for uppercase, digit and a special character. Weak passwords are rejected.

Why is it important - 
Prevents the user from setting easy-to-guess passwords like '123456' or 'password'.

c. Login Attempt Limit - 

How I implemented it -

A counter starts at 3 and decreases each time the wrong password is entered. When the attempts reach 0, the system temporarily locks the account for 60 seconds using Python’s time module and a dictionary that stores lock expiration times.

Why is it important -

This helps reduce brute-force attacks by preventing repeated login attempts within a short period of time.

d. Audit Logging - 

How I implemented it -
Every action calls write_log() which appends a timestamped message to
audit.log.

Why is it important - 
Provides a traceable record of all activity. This is important for detecting suspicious behavior.

e. Password Confirmation on Update- 

How I implemented it - 
When updating , the user types the new password twice and they must match.

Why is it important -
Stops the user from accidentally saving a mistyped new password and getting locked out.

f. Current Password Verification - 

How I implemented it -
Before or deleting, the user must prove they know the current password.

Why is it important -
Stops someone who has left their computer unlocked from having their account changed.

g. Delete Confirmation - 

How I implemented it -
The user must type 'yes' before an account is deleted.

Why is it important -
Prevents accidental deletion, an extra step so it cannot happen by mistake.

h. Sesssion Validation - 

How I implemented it -
The program keeps track of whether a user is logged in using a login state variable

Why is it important - 
This prevents the user from logging out before successfully logging in and improves the logical flow of the system.

i. Temporary Account Lockout -

How I implemented it -

The system temporarily locks user accounts for 60 seconds after multiple failed login attempts using Python’s time module.

Why is it important -

This reduces repeated password guessing attempts and improves login security.

## How Logging works - 

The system logs the key user actions in a file named audit.log. Whenever any event occurs such as registering, logging in, entering the incorrect password, deleting an account or clearing the log, the program makes a call to write_log() function.

This function will append a time and a message to the log file. The log assists in tracking system activity and is also an important audit trail that can assist in monitoring security and detecting suspicious activity.

## Error Handling Section -

I implemented basic error handling to make the system more reliable and user-friendly.

. The system checks for empty usernames and passwords

. Prevents duplicate usernames during registration

. Displays clear error messages when incorrect passwords are entered

. Handles missing log files safely when viewing logs 

. Asks for confirmation before deleting accounts or clearing logs

## Limitations and What Could be Improved

I want to be honest about what this system does not do perfectly because I think it is important to understand where the weaknesses are:

. Temporary lockout data is not permanently stored -

The temporary account lock is stored only while the program is running. If the program restarts, the lock information is reset.

. No admin role - 

Any user can view or clear the log file. In an actual system, these would only be accessible to an administrator.

. Limited session management - 

The system now tracks whether a user is logged in before allowing logout, but it does not implement advanced session handling such as session expiration or user-specific session tokens.

. Terminal only - 

The entire process is executed in the command line. Some actual implementation would have a decent UI.

## Code structure

I chose to divide the code into three files due to the fact that it would look cleaner and easier to control:

Main.py merely deals with the menu and user interface. It takes over the functions of the auth.py and Utils.py and invokes the correct one based on the choice made by the user.

auth.py deals with all the authentication related functions such as registration, login, password update, logout, account deletion, and log manahgement

utils.py deals with reusable helper functions such as password hashing, logging, password strngth validation and file handling.

Such a strategy is referred to as separation of concerns. It implies that there is a single explicit job with each file. Another effect of this was that testing each of the functions could be done without re-running the while menu each time.
